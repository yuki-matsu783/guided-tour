# Claude への指示をどこに置くか

常に読ませられる量には限りがある。全部を `CLAUDE.md` に書くと肝心の指示が埋もれる。情報ごとに、いつ読まれるべきかで置き場を分ける。

| 置き場 | 読まれるとき | 置くもの |
|---|---|---|
| `CLAUDE.md` | 常に | 常に守る決まりと、詳細への索引。短く保つ |
| `docs/claude/` | 索引から引いたとき | 理由・手順・例を含む開発の決まり |
| `.claude/skills/` | 該当する作業のとき | 長い手順、このプロジェクト向けに一般論を上書きする箇所 |
| 型・lint・依存検査 | 機械が常に | 守らせたい規約（[書けなくする](enforcement.md)） |
| `docs/`（要件・設計・ADR） | 索引から引いたとき | 作るものの記述と決定の記録 |

## `CLAUDE.md` と `docs/claude/` に書くもの

- 事実
- 禁止事項
- 正の文書への道案内

手順はスキルへ、決定の中身は ADR へ、コードを読めば分かることはコードへ置く。値や閾値は写さず出典を指す。

## ルールとスキルのどちらか

次の3つの問いを上から。

1. 近くのファイルを真似すれば同じように書けるか → 書けるなら、どちらにも書かない
2. その決まりが破られるのは、スキルが読み込まれている作業の最中か → そうでなければ、ルールに置く
3. 破られても、テストや lint で気づけないか → 気づけないなら、ルールに置く

例：「本番コードにテスト都合の分岐を足さない」は本番コードを書いている最中に破られ、そのときテストのスキルは読まれないのでルール。
「エラーの文言でアサートしない」はテストを書いている最中に破られるのでスキル。

## 索引を育てる

- 触る領域ごとに、必読の文書（要件・設計・ADR）を `CLAUDE.md` から引ける表にする。ソースが育って領域が決まったら作る
- 新しい決まりは、まず `docs/claude/` に書き、`CLAUDE.md` の表に1行足す
- 同じ指摘を利用者から繰り返し受けたら、その決まりを文書か検査に落とす。口頭の指摘のまま残さない
