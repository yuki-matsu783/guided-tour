# 守らせるより書けなくする

規約は、文書に「こうする」と書いて守らせるより、違反そのものを起こせなくする。守られたかを人が確かめる状態を作らない。

## 手段の優先順位

上から順に、使えるものを選ぶ。

| 順 | 手段 | 例 |
|---|---|---|
| 1 | 型で表現できなくする | 識別子は `string` ではなく branded type にし、生成は zod の検証を通す関数だけにする |
| 2 | 型の抜け道を lint で塞ぐ | `as <branded type>` による型の偽造を lint で禁止する |
| 3 | 依存方向を検査する | 実行場所をまたぐ import を依存検査で禁止する（例：ページ側から `chrome.storage` の層を読まない） |
| 4 | ビルドで落とす | `pnpm run typecheck` と `pnpm run test` が通らなければ `pnpm run build` を失敗させる |
| 5 | 文書に書く | 上の4つで止められないものだけ。事実・禁止・出典への道案内に限る |

## 型の使い方

- 対応表は `satisfies Record<Union, T>` で書く。union にメンバーを足した瞬間、表の更新漏れが型エラーになる
- 外から入る値（ツアー、メッセージ、storage の値）は zod で検証し、検証を通った型だけを内側に渡す
- `any` と、型を偽る `as` を使わない。`unknown` と型の絞り込みを使う

## 検査を弱めない

- lint・型・テストの設定ファイルを、違反を消すために緩めない。緩める必要が出たら、理由を示して利用者に確かめる
- テストが通らないとき、テストケースを削って通さない（[進め方](workflow.md)の承認済みテストケースの扱い）
- 設定ファイルへの編集を止める仕組み（フック）は、導入したらここに書く

## 文書に書かないもの

lint・型・テストで止まるものは、`CLAUDE.md` にも `docs/claude/` にも書かない。書くと検査と二重になり、食い違う。
