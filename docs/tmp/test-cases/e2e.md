# 結合テスト（E2E）のテストケース一覧

実装の前に利用者の承認を得るための、説明文だけの一覧。テストコードは書かない。

## 前提

- Playwright で拡張機能を読み込んだ Chromium（`launchPersistentContext`）を使う。Service Worker の停止は CDP（`ServiceWorker.stopWorker` など）で行う。
- サイドパネルは Playwright から直接操作できないため、`chrome-extension://<ID>/sidepanel.html` を通常のタブで開いて操作する（仕様の疑問 Q-2）。ID は固定されているので、ツアー側の `origins` は変わらない。
- テスト用ページはローカルのサーバーで配る。ホストは `localhost` と `127.0.0.1` を別サイトとして使い分ける（複数サイトのケース用）。
- テスト用ツアーは `tests/e2e/fixtures/` に置く（`.yaml` と `.zip`）。同梱ツアーは使わない。ただし E-83〜E-86 は自己紹介ツアーを使う。
- 「単体で補う」はE2Eでは確かめにくく、Vitest で確かめる。「手動」はリリース前の確認表で確かめる。両方を併記したものは、E2E で確かめられる範囲だけを手順に書いた。

## テスト用ページ

| 記号 | ページ | 内容 |
|---|---|---|
| P-A | 静的 | 対象要素が最初から存在し、変化しない。ボタン・入力欄・見出し |
| P-B | GitLab 風 | トークン発行画面を模す。`?lang=en` と `?lang=ja` で名前が変わる。ID なし、役割と名前で特定する構成 |
| P-C | 社内ツール風（日本語版） | 日本語の名前・ラベルのフォーム。`data-tour-id` あり |
| P-D | 社内ツール風（英語版） | P-C の英語表示。`data-tour-id` なし。名前の候補で照合する |
| P-E | 再描画 | ボタンで対象要素を別の要素に入れ替える（同じ条件の新しい要素） |
| P-F | 属性書き換え | 同じ要素の `role`・所属する領域・名前・`aria-hidden` などを、ボタンで書き換える |
| P-G | ID 付け替え | `data-tour-id` を別の要素へ付け替える。役割・名前・領域が違う要素を持つ |
| P-H | `display: contents` | 祖先に `display: contents` を持つ対象要素 |
| P-I | 完了ページへ遷移 | `/tokens/new` のフォームで作成すると `/tokens/created` へ遷移する |
| P-J | 非常に長い URL | パスが数千区間、またはクエリが非常に長い URL で開くページ |
| P-K | 遅延追加 | 対象要素が最初は無く、指定した秒数の後に追加される |
| P-L | 曖昧な候補 | 同名ボタンが2つ。同じ祖先に読み替えられる2つ。探す範囲が複数一致する |
| P-M | 読み替え先 | `highlight.closest` が `body` になる指定と、表示領域より長いフォーム |
| P-N | password 欄 | `type="password"` の欄と、通常の入力欄 |
| P-O | 右端の要素 | 対象要素が画面右端に張り付く |
| P-P | 不一致ページ | URL 条件に合わない同一オリジンのページ（`/project-danger` など） |
| P-Q | 別オリジン | `127.0.0.1` 側の静的ページ（複数サイト・origins 外のケース用） |
| P-X | example.com 模擬 | Playwright の `context.route` で `https://example.com/` に、実物と同じ構造（見出し「Example Domain」、リンク「Learn more」）を返す。名前を旧表記「More information...」に変えた版と、通信失敗（abort）版も持つ |
