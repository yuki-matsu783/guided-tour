# 単体テストケース：ツアー形式・URL 条件・パッケージ取り込み

説明文だけの一覧。テストコードは承認後に書く。方法は Vitest（取り込みは fake-indexeddb と、悪意あるファイルを集めた資料を併用）。
境界値は「上限ちょうど（成功）」と「上限+1（失敗）」の組で書く。

## ツアー形式・検証（core/tour）

対象は `parseTour(yamlText, fileName)`。エラーは `{ file, line, path, message }`。

## ツアーパッケージの取り込み（core/package、sidepanel/import）

対象は `importFiles(files[])`。zip は fflate で作ったテスト用の資料、保存は fake-indexeddb。
結果は、ファイルごとの成功（ツアー名・対象サイト・警告）または失敗（エラーの一覧）。

### 入力の受け付け

| ID | テストケース（説明） | 根拠 |
|---|---|---|

- Q2 `done.type` ごとの必須・禁止の項目（page には url が必須か、element・state には target が必須か、state には `state` が必須か、他の組み合わせは禁止か）が、設計書で `?` のみになっている。
- Q3 `kind: guide` の step が、禁止の3項目（`target`・`url`・`done`）以外の項目（`tab`・`open`・`media`・`tip`）を持てるか。
- Q4 step の `id` の重複、役割（`tab`）が `tabs` に定義されていない場合の扱いが書かれていない。FR-37 が stepId に頼るので、重複はエラーが望ましい。
- Q5 URL 条件のパスの「正規表現の記号らしきもの」の範囲が「など」のまま。禁止する文字の一覧（`^`・`+`・`?`・`{`・`|`・`*` の区間内など）が必要。
- Q6 マージキー（`<<`）は「無効」とあるが、エラーにするか、通常のキーとして残すかが書かれていない。
- Q7 空のファイル、複数のドキュメント、最上位が配列のときの扱いと、構文エラーのときに形式の検証へ進むかが書かれていない。
- Q8 「手がかりの候補数 各20」がどの項目に及ぶか（`name[]`・`label[]`・`text[]`・`css[]` のすべてか）と、`steps` 以外の `origins` や `tabs` の件数の上限が書かれていない。
- Q9 必須の項目が欠けているエラーの行番号を、親のどの行にするか（親のキーの行か、その直前か）が書かれていない。
- Q10 警告の件数に上限（エラーは20）があるか、書かれていない。
- Q11 `matchUrl` が、解析できない URL・http/https 以外のスキームの URL を受け取ったときの扱いが書かれていない。
- Q12 `prefix: /` や、`exact: /` と `path` 省略の違いの扱いが書かれていない（区間が0個のときの扱い）。
- Q13 `*` を区間の途中に書く（`/a/b*`）ことを許すか、エラーにするかが書かれていない。FR-68 では `*` が1区間全体に一致するとだけある。
- Q14 FR-12 の「区切り文字を変形したもの（`¥` など）」の具体的な範囲が書かれていない。設計書の検査項目は `\`・NUL・絶対パス・ドライブ名・空の区間・`..`・シンボリックリンクで、`¥` は含まれていない。
- Q15 zip のディレクトリのエントリ（末尾が `/`）が「空の区間」として拒否されるか、ファイル数500に数えられるかが書かれていない。
- Q16 参照されていないファイルを、保存するか捨てるか、容量の予約に数えるかが書かれていない。
- Q17 `body` と `bodyFile` を両方書いた場合、`bodyFile` の拡張子の制限（`.md` のみか）が書かれていない。
- Q18 画像の「4096×4096 px 以内、かつ 1,600万画素以内」は、4096×4096（約1,678万画素）がそれ自体で後者の上限を超え、矛盾して見える。画素数の上限が実質的な制限になる。
- Q19 上書きを承認しなかった結果を、失敗（エラー）とするか、取り消しとして別の結果にするか。また、確認を出す前に検証を行うか（設計書の順序は検証が先）。
- Q20 1回の取り込みに同じ ID が複数ある場合、同時の取り込みで同じ ID が競合する場合の扱い（後勝ち、先勝ち、確認の回数）が書かれていない。
- Q21 `totalBytes` の定義（保存するファイルの `size` の合計か、yamlText を含むか）と、上書き時に旧版の分を予約から差し引いて判定するかが書かれていない。旧版を差し引かないと、上限近くで同じツアーを更新できなくなる。
- Q22 取り込み済みツアーの削除時に、`files` と `meta.totalBytes` を更新するかが、この範囲の設計書に書かれていない（削除はバックグラウンドの `REMOVE` の担当か）。
- Q23 `CATALOG_CHANGED` の送信が失敗したとき（バックグラウンドが起動中でない、など）の再送・エラー表示が書かれていない。
- Q24 zip の「20 MB」「50 MB」「200 MB」の MB が 10^6 か 2^20 かが書かれていない。境界値のテストの値が変わる。
