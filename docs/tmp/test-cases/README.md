## 既定の解釈

### ツアー形式・URL 条件・取り込み（core-tour-package の Q 番号）

| Q | 解釈 |
|---|---|
| 1 | 未知の項目はエラー（誤字を作成者に気づかせる） |
| 2 | `done.type: page` は `url` 必須・`target`/`state` 禁止。`element` は `target` 必須。`state` は `target` と `state` 必須。それ以外の組み合わせはエラー |
| 3 | `kind: guide` は `target`・`url`・`done`・`tab`・`open` を持てない。`tip`・`media`・`body`/`bodyFile` は持てる |
| 4 | step の `id` の重複はエラー。`tabs` に無い役割を使う page ステップはエラー（`tabs` を省いた場合は `main` だけが暗黙にある） |
| 5 | パスで禁止する記号は `( ) [ ] { } \ $ ^ + ? \|`。`*` と `**` は区間全体としてだけ書ける |
| 6 | マージキー `<<` はエラー |
| 7 | 空・複数ドキュメント・最上位が対応表でないものはエラー。構文エラーがあれば形式の検証へ進まない |
| 8 | 候補数 20 は `name`・`label`・`text`・`css` のそれぞれに適用。`origins` と `tabs` も各 20 まで |
| 9 | 必須の項目が欠けたエラーの行番号は、親の対応表の行 |
| 10 | 警告も最大 20 件 |
| 11 | 解析できない URL、http/https 以外の URL は不一致 |
| 12 | `path` 省略はオリジン全体。`prefix: /` も全体。`exact: /` はルートだけ |
| 13 | 区間の途中の `*`（`/a/b*`）はエラー |
| 14 | ファイル名の `¥`(U+00A5)・`₩`(U+20A9)・`／`(U+FF0F)・`＼`(U+FF3C)・`∕`(U+2215)・`⁄`(U+2044) を拒否 |
| 15 | ディレクトリのエントリは無視し、ファイル数に数えない |
| 16 | ファイル数の上限は展開時にすべてのエントリで数える。保存するのは `tour.yaml` と参照されたファイルだけ |
| 17 | `body` と `bodyFile` の両方はエラー。`bodyFile` は `.md` だけ |
| 18 | 書かれたとおり両方を満たす必要がある（4096×4096 は画素数で拒否） |
| 19 | 検証を先に行い、通ったものだけ上書きを確認する。承認しなければ「取り消し」として結果を返す（エラーではない） |
| 20 | 1回の取り込みで同じ ID が複数あれば、後のものをエラーにする。別々の取り込みの競合は、確認をそれぞれ出し、保存はトランザクション順（後勝ち） |
| 21 | `totalBytes` は保存するファイルの `size` と `yamlText` のバイト数の合計。上書きでは旧版の分を差し引いて判定する |
| 22 | 削除はバックグラウンドのツアー管理が行い、`files` と `meta.totalBytes` を戻す |
| 23 | `CATALOG_CHANGED` が届かなくても取り込みは成功とする。バックグラウンドは起動時と次の一覧取得時に IndexedDB から組み立て直す |
| 24 | MB は 2^20 バイト |

### 要素特定・Markdown・ログ・保守記録（locator-markdown-logging の Q 番号）

| Q | 解釈 |
|---|---|
| 1 | 段階1は `tourId` と `testId` の両方に一致する要素を集めた和集合で、1件に決まれば採用 |
| 2 | `match` は段階4の `text[]` だけに効く。名前の照合（段階2・3、補助、`require.name`）は正規化後の完全一致 |
| 3 | リンクはホスト名（`URL.hostname`）だけを `origins` のホスト名と比べる。方式・ポートは見ない。サブドメインは別ホスト |
| 4 | 読み替えがないときも、操作対象そのものに不適格の判定をかける |
| 6 | 手がかりが1つもない target は取り込み時にエラー（`target` を書くなら手がかりが要る） |
| 7 | 自前の表示のホスト要素は専用の属性で見分け、`within` の解決でも除外する |
| 8 | Markdown の h1〜h4 を h2〜h5 として表示する。h5・h6 は段落として表示する |
| 9 | 代替文が空の画像は取り込み時にエラー。描画側は代替文が空でも壊れない |
| 10 | 同じコンテナへの再描画は中身を置き換える |
| 11 | `logger.invalid` に残す出来事の名前は、スキーマに登録された名前のときだけ。登録外は固定の `unknown` |
| 12・15 | スキーマの検査はレベルの判定より先に行う |
| 13 | 理由コードは呼び出し側で列挙値として渡す。無ければ `unknown`。スタックは残さない |
| 14 | 不正な `logLevel` は既定の warn として扱う |
| 16 | 2秒はまとめの最初の1件から数える。50件に達したらすぐ書く |
| 17 | ちょうど30日前のものは残す。30日で消してから新しい順に 2,000 件を残す |
| 18 | 書き出しの前に、まとめ待ちのログを書き込む |
| 19 | 書き出しは古い順 |
| 20 | 同じ `(sessionId, gen, reason)` の重複は何も更新しない。消去・ツアー削除で記憶も消える |
| 21 | 「3→4→3」は `gen` が変わるので、戻った3も1回数える |
| 22 | `lastAt` が同じものは鍵の順で消す |
| 23 | 書き出しに `lastKey` は含めない |
| 24 | 保守記録の保存失敗もログと同じく、古いものを消して1回だけ再試行する |

### ページ側・バックグラウンド（content-background の疑問）

| 疑問 | 解釈 |
|---|---|
| `saveError` を下ろす条件 | storage.session と storage.local の両方が成功したときだけ |
| 重複した `opId` | 前回と同じ結果を返し、状態は変えない。識別子の不一致で捨てた操作の `opId` は記憶しない |
| `goto` の範囲外 | 捨てる |
| 実行中・一時中断中の `START` | 拒否する（サイドパネルは開始ボタンを出さない） |
| `RESUME_NEW` | 上書きによる一時中断のときだけ受け付ける |
| 8秒以降の低頻度探索 | 2秒ごとに、前回からページの変化があったときだけ探索する |
| `selected` が偽になったとき | ハイライトと吹き出しを消す（ミニガイドは残す）。真に戻ったらすぐ探索する |
| 8秒の起点 | ステップに入ったとき・再確認・喪失・`selected` が真に戻ったとき。ただし自動スクロールは、ステップに入ってから8秒以内に限る |
| 吹き出しが下・上・左のどこにも収まらない | 下に置き、表示領域の中に寄せる |
| ホバー状態のバーのクリック | 展開する（一時的な展開）。一時的な展開では `SET_UI` を送らない |
| `getPinned` で旧版がない | 無しを返す。上書きは一時中断が先に確定するため、旧版の内容は使わない |
| `permissions.onRemoved` | 実行中のツアーのパターンが1つでも失われたときだけ一時中断する |
| `unsupported` | 権限がない、または `scripting.executeScript` が失敗したとき |

### E2E（e2e の Q 番号）

| Q | 解釈 |
|---|---|
| 1 | E2E はテスト用の manifest（localhost を host_permissions に足す）で行う。許可のダイアログ（AC-04・24・62 の許可の部分）は単体テストと手動で確かめる。本番のコードに試験用の分岐は入れない |
| 2 | サイドパネルは `chrome-extension://<id>/sidepanel.html` を別ウィンドウのタブで開いて操作する |
| 3 | ブラウザの再起動で残るのは進捗だけ。「続きから」で同じステップから再開できることを確かめる |
| 4 | 保存失敗（AC-67・68）は単体テストで確かめる |
| 5 | FR-33 の「FR-73 の手段」は FR-85 の誤記として要件書を直す |
| 6 | リポジトリに既存実装と「同梱3ツアー」が無いため、同梱は自己紹介ツアーだけになる。AC-38（英語表示の GitLab）は、GitLab 風のテスト用ページとテスト用ツアーで E2E を行い、実サイトでの確認は手動とする |
