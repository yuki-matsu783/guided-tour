# ADR-0069: 技術検証の結果の反映（設計書）

状態: 採用

## 決めたこと

- ツアーパッケージの展開では、圧縮側のデータを 4 KB 以下に区切って fflate に渡し、展開結果を受け取るたびに合計を確かめる。エントリが宣言する展開後のサイズは判定に使わない
- ページ側からのメッセージの `sender.url` は、ページの現在の URL の判定に使わない。現在の URL は `chrome.tabs` で取得したタブの URL を使う

## 理由

- fflate の同期の `UnzipInflate` は、1回の入力から展開した結果を1回にまとめて返す。上限を超えて展開してしまう量は、1回に渡す圧縮側の大きさにほぼ比例する（実測で、4 KB ずつなら約 2 MB、64 KB ずつなら約 64 MB の超過、全体を1回で渡すと打ち切れない）。宣言サイズは zip の中で偽れる
- `sender.url` は、同じ文書内で `pushState` により URL が変わった後も、変わる前の URL のままだった

## 得たもの・失ったもの

- 展開後の合計の上限を、圧縮率によらず数 MB の超過に抑えられる。区切る分だけ、展開の呼び出し回数が増える
