# ADR-0070: 手がかりごとの探す範囲（設計書）

状態: 採用

## 決めたこと

- `target.within` は、すべての段階に効く既定の範囲とする。書かなければページ全体
- 段階2〜5の手がかり（`name`・`label`・`text`・`css`）は、候補の配列のほかに `{ values: [...], within: <範囲> | page }` の形でも書ける。`within` を書いた手がかりは、既定の範囲の代わりにその範囲で探す。`page` はページ全体を明示する
- 段階1（`tourId`・`testId`）は、既定の範囲で探す
- 範囲が0件か2件以上に一致したら、その範囲を使う段階だけを失敗とする。ページ全体へは広げない（ページ全体で探すのは、`page` を明示したときだけ）

## 理由

- 段階1と段階4が範囲を無視してページ全体を探す実装になっており、範囲の外の同じ名前の要素を採用していた。範囲の解釈が段階によって違うと、作成者が書いた範囲が効かない
- target に範囲が1つしか書けないと、「この段階だけは別の範囲で探したい」という書き分けができない。対象サイトの画面の変更に備えて段階ごとの逃げ道を書けるほうが、ツアーを長く保守できる（利用者の判断）
- ページ全体へ黙って広げると、範囲を書いた意図に反して別の要素を指すおそれがある。広げるのは作成者が明示したときに限る

## 得たもの・失ったもの

- 段階ごとに範囲を書き分けられる。範囲の扱いが全段階で同じになる
- ツアー形式の手がかりの書き方が、配列と対応表の2通りになる

## 採らなかった案

- target の `within` を1つだけ持ち、全段階に効かせる案。形式は変わらないが、段階ごとの書き分けができない
